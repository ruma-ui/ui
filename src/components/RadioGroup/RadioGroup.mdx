## Overview

The RadioGroup component provides a set of mutually exclusive options where users can select exactly one choice. It offers full customization with support for icons, descriptions, horizontal/vertical layouts, error states, and comprehensive accessibility features.

## Accessibility

The RadioGroup component follows WAI-ARIA guidelines and includes comprehensive accessibility features:

- **Semantic HTML**: Uses proper `radiogroup` role and fieldset structure
- **Keyboard Navigation**: Full keyboard support with arrow keys and tab navigation
- **Screen Reader Support**: Proper announcements of options, selections, and descriptions
- **Focus Management**: Clear focus indicators and logical focus flow
- **Error Handling**: Accessible error messages linked to the radio group
- **Required Fields**: Proper `aria-required` and visual indication for required fields
- **Label Association**: Proper label association for all radio options

## Best Practices

### When to Use

- **Mutually Exclusive Options**: When users must select exactly one option from a set
- **Clear Choices**: When all options should be visible and comparable
- **Form Inputs**: For form fields requiring a single selection
- **Settings and Preferences**: For configuration options with clear alternatives

### When Not to Use

- **Multiple Selections**: Use checkboxes or a multi-select component instead
- **Many Options**: Consider a select dropdown for more than 6-8 options
- **Binary Choices**: Consider a switch for simple on/off or yes/no choices
- **Actions**: Use buttons for actions that trigger immediate behavior

### Guidelines

- **Clear Labels**: Use descriptive, concise labels that clearly differentiate options
- **Logical Ordering**: Order options by importance, frequency of use, or alphabetically
- **Consistent Options**: Ensure options are mutually exclusive and complete
- **Group Related Options**: Keep related radio groups close together
- **Default Selections**: Consider pre-selecting the most common or recommended option
- **Error Handling**: Provide clear validation messages for required fields
- **Mobile Considerations**: Ensure adequate touch targets and consider vertical layouts
- **Descriptions**: Use option descriptions for complex choices that need clarification
