## Overview

NavigationMenu provides a flexible and accessible navigation component that supports both horizontal and vertical orientations, with support for nested menus and submenus. It follows modern design patterns and includes comprehensive keyboard navigation and screen reader support.

## Component API

<ArgTypes of={NavigationMenuStories} />

### NavigationMenu `orientation`

The `orientation` prop controls the layout direction of the navigation menu. Choose "horizontal" for top navigation bars and "vertical" for sidebars and mobile menus.

### NavigationMenu `size`

The `size` prop controls the overall size of navigation items. Available options are "sm", "md", and "lg", providing appropriate padding and font sizes for different contexts.

### NavigationMenu `variant`

The `variant` prop determines the visual style of the navigation menu. Options include "default" for standard navigation, "underline" for active state indicators, and "pills" for a more contained appearance.

## Accessibility

Our NavigationMenu component follows accessibility best practices:

- **Semantic HTML**: Uses proper `<nav>`, `<ul>`, `<li>`, and `<a>` elements with correct ARIA attributes
- **Keyboard Navigation**: Full support for Tab, Enter, Space, and arrow key navigation
- **Screen Reader Support**: Proper labeling with `aria-expanded`, `aria-haspopup`, and `role` attributes
- **Focus Management**: Clear focus indicators and logical tab order
- **State Communication**: Menu expansion states are properly communicated to assistive technologies
- **Disabled States**: Properly communicated via `aria-disabled` and `disabled` attributes

## Best Practices

### Do's ✅

- Use clear, descriptive labels for navigation items
- Keep navigation hierarchy shallow (avoid deeply nested submenus)
- Use icons consistently across navigation items when applicable
- Provide adequate spacing between navigation items
- Consider using the `active` prop to highlight the current page/section
- Test navigation on mobile devices and ensure touch targets are adequate
- Use semantic HTML structure for SEO benefits

### Don'ts ❌

- Don't hide critical navigation behind complex submenu structures
- Avoid using navigation for actions that could be better served by buttons
- Don't make navigation items too small on touch devices
- Avoid inconsistent navigation patterns across your application
- Don't overload navigation items with too much text or icons
- Avoid using navigation for content that changes frequently

### Navigation Structure

```jsx
// Recommended: Clear hierarchy
<NavigationMenu orientation="horizontal">
  <NavigationMenuList>
    <NavigationMenuItem value="home">
      <NavigationMenuLink href="/">Home</NavigationMenuLink>
    </NavigationMenuItem>
    <NavigationMenuItem value="products">
      <NavigationMenuTrigger>Products</NavigationMenuTrigger>
      <NavigationMenuContent>
        <NavigationMenuGroup title="Categories">
          <NavigationMenuLink href="/electronics">Electronics</NavigationMenuLink>
          <NavigationMenuLink href="/clothing">Clothing</NavigationMenuLink>
        </NavigationMenuGroup>
      </NavigationMenuContent>
    </NavigationMenuItem>
  </NavigationMenuList>
</NavigationMenu>

// For mobile: Consider collapsible navigation
<NavigationMenu orientation="vertical">
  <NavigationMenuList>
    {/* Navigation items */}
  </NavigationMenuList>
</NavigationMenu>
```

### Active State Management

```jsx
// Highlight current page
const currentPath = window.location.pathname;

<NavigationMenuItem value="dashboard" active={currentPath === "/dashboard"}>
    <NavigationMenuLink href="/dashboard">Dashboard</NavigationMenuLink>
</NavigationMenuItem>;
```
