## Overview

Buttons are clickable elements that trigger actions and allow users to interact with the interface. They communicate calls to action clearly and help users navigate through workflows. Our Button component is designed to be flexible, accessible, and production-ready with multiple variants and customization options.

<Canvas of={ButtonStories.Primary} />

## Variants

### Primary Variant

The primary button is used for the main action on a page or in a section. Use primary buttons sparingly—typically only one per page or modal to avoid confusion about the primary action.

<Canvas of={ButtonStories.Primary} />

### Secondary Variant

Secondary buttons are used for secondary actions that are important but not the primary focus. They work well alongside primary buttons or when you need multiple actions of similar importance.

<Canvas of={ButtonStories.Secondary} />

### Tertiary Variant

Tertiary buttons are subtle and work well for less important actions or in dense interfaces where you need to minimize visual weight.

<Canvas of={ButtonStories.tertiary} />

### Outline Variant

Outline buttons provide a middle ground between secondary and tertiary buttons. They're great for actions that need more emphasis than tertiary buttons but less than filled buttons.

<Canvas of={ButtonStories.Outline} />

### Destructive Variant

Use destructive buttons for actions that delete, remove, or cause irreversible changes. The red color provides a clear visual cue about the potentially harmful nature of the action.

<Canvas of={ButtonStories.Destructive} />

### None Variant

The none variant provides a completely unstyled button that can be customized with your own styles via the `className` prop.

<Canvas of={ButtonStories.None} />

### Button `variant`

The `variant` prop determines the visual style and hierarchy of the button. Choose the appropriate variant based on the action's importance and context.

```jsx
<Button variant="primary">Primary Action</Button>
<Button variant="secondary">Secondary Action</Button>
<Button variant="tertiary">Subtle Action</Button>
<Button variant="outline">Outline Action</Button>
<Button variant="destructive">Delete Action</Button>
<Button variant="none">Unstyled Button</Button>
```

Add subtle animation effects to enhance user interactions and provide visual feedback. These animations are designed to improve usability and user experience.

**Animation Guide:**

- **Scale**: Slightly enlarges on hover, shrinks on click - great for primary actions
- **Glow**: Adds a colored shadow glow - draws attention to important buttons
- **Lift**: Combines upward movement with shadow - modern Material Design feel
- **Ripple**: Creates a ripple effect overlay - excellent user feedback
- **Press**: Only animates on click - minimal but responsive feel

## Accessibility

Our Button component follows accessibility best practices:

- **Semantic HTML**: Uses proper `<button>` elements with correct ARIA attributes
- **Keyboard Navigation**: Full support for Enter and Space key activation
- **Screen Reader Support**: Proper labeling with `aria-label`, `aria-disabled`, and `aria-busy`
- **Focus Management**: Clear focus indicators and logical tab order
- **Loading States**: Communicated to assistive technologies via `aria-busy`
- **Disabled States**: Properly communicated via `aria-disabled` and `disabled` attributes

## Best Practices

### Do's ✅

- Use clear, action-oriented labels (e.g., "Save Changes" instead of "OK")
- Maintain consistent button hierarchy across your interface
- Place primary actions on the right, secondary on the left
- Use loading states for operations that take time
- Provide adequate spacing between buttons (8px minimum)
- Use icons that enhance clarity, not decoration

### Don'ts ❌

- Don't use more than one primary button per page section
- Avoid vague labels like "Click Here" or "Submit"
- Don't make buttons too small (minimum 44px height for touch targets)
- Avoid using destructive buttons for non-destructive actions
- Don't rely solely on color to convey meaning

### Button Combinations

```jsx
// Recommended: Secondary + Primary
<div style={{ display: 'flex', gap: '8px' }}>
  <Button variant="secondary">Cancel</Button>
  <Button variant="primary">Save Changes</Button>
</div>

// Form actions
<div style={{ display: 'flex', gap: '8px' }}>
  <Button variant="tertiary">Reset</Button>
  <Button variant="outline">Save Draft</Button>
  <Button variant="primary">Publish</Button>
</div>
```
