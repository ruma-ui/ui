## ToastProvider

The ToastProvider component manages toast state and provides a convenient hook-based API for showing toasts throughout your application.

### Basic Usage

Use the `useToast` hook to access toast functions like `success()`, `error()`, `warning()`, and `info()`.

```jsx
import { ToastProvider, useToast } from "@/components/Toast";

function MyComponent() {
    const { success, error } = useToast();

    const handleSave = () => {
        try {
            // Save operation
            success("Data saved successfully!");
        } catch {
            error("Failed to save data");
        }
    };

    return <button onClick={handleSave}>Save</button>;
}

// Wrap your app with ToastProvider
function App() {
    return (
        <ToastProvider>
            <MyComponent />
        </ToastProvider>
    );
}
```

### Promise Toasts

Handle asynchronous operations with promise-based toasts that automatically show loading, success, and error states.

```jsx
const { promise } = useToast();

const handleAsyncOperation = async () => {
    const result = await promise(fetchData(), {
        loading: "Loading data...",
        success: "Data loaded successfully!",
        error: "Failed to load data",
    });
};
```

## Component API

<ArgTypes of={Toast} />

### Toast `variant`

The `variant` prop determines the semantic meaning, color scheme, and default icon of the toast.

```jsx
<Toast variant="success" title="Success!" description="Operation completed" onClose={() => {}} />
<Toast variant="error" title="Error" description="Something went wrong" onClose={() => {}} />
<Toast variant="warning" title="Warning" description="Please check your input" onClose={() => {}} />
<Toast variant="info" title="Info" description="Here's some information" onClose={() => {}} />
```

### Toast `position`

The `position` prop controls where the toast appears on screen. Choose positions that don't interfere with important interface elements.

```jsx
<Toast position="top-left" title="Top Left" onClose={() => {}} />
<Toast position="top-center" title="Top Center" onClose={() => {}} />
<Toast position="top-right" title="Top Right" onClose={() => {}} />
<Toast position="bottom-left" title="Bottom Left" onClose={() => {}} />
<Toast position="bottom-center" title="Bottom Center" onClose={() => {}} />
<Toast position="bottom-right" title="Bottom Right" onClose={() => {}} />
```

### Toast `size`

The `size` prop controls the toast's dimensions and typography scale. Choose sizes based on content length and visual hierarchy.

```jsx
<Toast size="sm" title="Small" description="Compact toast" onClose={() => {}} />
<Toast size="md" title="Medium" description="Standard toast size" onClose={() => {}} />
<Toast size="lg" title="Large" description="Prominent toast with more space" onClose={() => {}} />
```

### Toast `duration`

The `duration` prop sets auto-dismiss delay in milliseconds. Set to 0 to disable auto-dismiss.

```jsx
<Toast duration={3000} title="3 second toast" onClose={() => {}} />
<Toast duration={0} title="Persistent toast" onClose={() => {}} />
```

### Toast `icon`

The `icon` prop accepts any React element to override the default variant icon.

```jsx
<Toast
    icon={<CustomIcon />}
    title="Custom Icon"
    description="Toast with custom icon"
    onClose={() => {}}
/>
```

### Toast `title` and `description`

The `title` and `description` props provide structured content. Use `title` for brief summaries and `description` for additional details.

```jsx
<Toast
    title="Operation Complete"
    description="Your data has been saved successfully"
    onClose={() => {}}
/>
```

### Toast `children`

The `children` prop allows fully custom content layout, overriding title/description structure.

```jsx
<Toast onClose={() => {}}>
    <div>
        <strong>Custom Content</strong>
        <p>Any React elements can be rendered here</p>
        <button>Action</button>
    </div>
</Toast>
```

### Toast `showCloseButton`

The `showCloseButton` prop controls visibility of the close button. Default is `true`.

```jsx
<Toast showCloseButton={false} title="No close button" onClose={() => {}} />
<Toast showCloseButton={true} title="With close button" onClose={() => {}} />
```

### Toast `animation`

The `animation` prop enables smooth enter/exit transitions. Default is `true`.

```jsx
<Toast animation={false} title="No animation" onClose={() => {}} />
<Toast animation={true} title="With animation" onClose={() => {}} />
```

## Accessibility

The Toast component follows accessibility best practices and includes:

- **ARIA Live Regions**: Automatic `aria-live="assertive"` for screen reader announcements
- **Semantic Roles**: Proper `role="alert"` for critical notifications
- **Keyboard Navigation**: Full keyboard support for interactive elements
- **Focus Management**: Clear focus indicators and proper focus handling
- **Screen Reader Support**: Comprehensive ARIA labeling with `aria-labelledby` and `aria-describedby`
- **Color Contrast**: All variants meet WCAG color contrast requirements
- **Motion Preferences**: Respects `prefers-reduced-motion` for animation control

## Best Practices

### When to Use

- **Operation Feedback**: Confirming successful actions or reporting errors
- **Status Updates**: Showing progress, completion, or system state changes
- **Alerts and Warnings**: Critical information requiring immediate attention
- **Non-intrusive Notifications**: Information that doesn't interrupt user workflow
- **Form Validation**: Displaying validation errors or success messages

### When Not to Use

- **Critical Actions**: Don't use toasts for destructive actions or important decisions
- **Persistent Information**: Avoid toasts for information users need to reference later
- **Complex Interactions**: Don't embed forms or complex UI in toasts
- **Navigation**: Don't use toasts as primary navigation or action triggers
- **Excessive Notifications**: Limit toast frequency to prevent user annoyance

### Guidelines

1. **Clear Messaging**: Use concise, actionable language that users understand immediately
2. **Appropriate Variants**: Choose variants that match the semantic meaning of the notification
3. **Consistent Positioning**: Use consistent positions across your application
4. **Auto-dismiss Timing**: Set appropriate durations based on content importance and length
5. **Manual Dismissal**: Always provide close buttons for persistent toasts
6. **Queue Management**: Handle multiple toasts gracefully without overwhelming users
7. **Mobile Considerations**: Ensure toasts work well on smaller screens and touch devices

### Content Guidelines

1. **Actionable Language**: Use verbs that suggest what happened or what users can do
2. **Error Specificity**: Provide specific error information when possible
3. **Success Confirmation**: Clearly indicate what operation succeeded
4. **Warning Clarity**: Explain what the warning means and potential consequences
5. **Progressive Disclosure**: Use title for summary, description for details

### Technical Guidelines

1. **Provider Setup**: Wrap your application root with `ToastProvider` for hook access
2. **Error Boundaries**: Handle toast errors gracefully to prevent crashes
3. **Performance**: Avoid creating toasts in rapid succession
4. **State Management**: Use appropriate state management for complex toast scenarios
5. **Testing**: Test toast behavior across different devices and screen readers
