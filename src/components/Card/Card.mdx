## Overview

Cards are versatile container components that group related content and actions together. They provide visual separation, hierarchy, and structure to your interface. Our Card component is designed to be flexible, accessible, and consistent with modern design patterns.

<Canvas of={CardStories.Default} />

## Variants

### Default Variant

The default card provides a clean, subtle container with a light border and minimal shadow.

<Canvas of={CardStories.Default} />

### Outlined Variant

The outlined variant features a more prominent border for better visual separation and hierarchy.

<Canvas of={CardStories.Outlined} />

### Elevated Variant

The elevated variant creates depth with enhanced shadows, making the card appear to float above the page.

<Canvas of={CardStories.Elevated} />

### Filled Variant

The filled variant has a subtle background color that provides additional visual hierarchy.

<Canvas of={CardStories.Filled} />

## Card Sections

Cards can be structured with distinct sections using CardHeader, CardBody, and CardFooter components.

### CardHeader

The header section typically contains titles, icons, or primary information.

### CardBody

The body section contains the main content of the card.

### CardFooter

The footer section usually contains actions, metadata, or secondary information.

## Accessibility

Our Card component follows accessibility best practices:

- **Semantic HTML**: Uses proper `<div>` or `<button>` elements based on interactivity
- **Keyboard Navigation**: Clickable cards support Enter and Space key activation
- **Focus Management**: Clear focus indicators for interactive cards
- **Screen Reader Support**: Proper ARIA attributes and semantic structure
- **Color Contrast**: Sufficient contrast ratios for text and borders
- **Motion Preferences**: Respects user's motion preferences for animations

## Best Practices

### Do's ✅

- Use cards to group related information and actions
- Maintain consistent card sizes within the same layout
- Use appropriate variants for different content hierarchies
- Provide clear visual feedback for interactive cards
- Use CardHeader, CardBody, and CardFooter for structured content
- Ensure adequate padding for comfortable reading
- Use shadows sparingly to avoid visual clutter

### Don'ts ❌

- Don't use cards for single, unrelated pieces of information
- Avoid mixing different variants in the same section unnecessarily
- Don't make cards too small for touch interaction (minimum 44px height for clickable cards)
- Avoid excessive padding that wastes space
- Don't rely solely on color to convey meaning
- Avoid using disabled state for permanent content
