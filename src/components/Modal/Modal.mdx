### Modal `variant`

The `variant` prop determines the visual style and background treatment of the modal. Choose the appropriate variant based on the modal's purpose and context.

```jsx
<Modal variant="primary" open={true} onClose={handleClose} title="Primary Modal">
  Primary modal content
</Modal>
<Modal variant="secondary" open={true} onClose={handleClose} title="Secondary Modal">
  Secondary modal content
</Modal>
```

```jsx
  Static modal content

```

## Accessibility

The Modal component follows WAI-ARIA guidelines and includes comprehensive accessibility features:

- **Focus Management**: Automatic focus to modal on open and return focus on close
- **Focus Trap**: Keyboard navigation stays within the modal when open
- **Keyboard Navigation**: Full support for Escape key closing and Tab navigation
- **Screen Reader Support**: Proper ARIA attributes including role, aria-modal, and aria-labelledby
- **Overlay Interaction**: Configurable overlay click behavior for different use cases

## Best Practices

### When to Use

- **Critical Actions**: For confirmations, alerts, or important user decisions
- **Forms**: When you need focused data entry without page navigation
- **Content Display**: For detailed information, images, or rich content overlays
- **Settings**: For configuration interfaces that benefit from focused interaction

### When Not to Use

- **Simple Messages**: Consider toast notifications for brief status messages
- **Navigation**: Don't use modals as primary navigation between app sections
- **Large Forms**: Consider dedicated pages for complex, multi-step forms
- **Frequent Actions**: Avoid modals for actions users perform repeatedly

### Guidelines

1. **Clear Purpose**: Every modal should have a specific, obvious purpose
2. **Focused Content**: Keep modal content focused and avoid information overload
3. **Obvious Exit**: Always provide clear ways to close the modal
4. **Responsive Design**: Ensure modals work well on all screen sizes
5. **Performance**: Use modals judiciously to avoid degrading page performance
6. **Accessibility**: Always provide proper ARIA labels and keyboard navigation

### Content Guidelines

1. **Concise Titles**: Use clear, descriptive titles that explain the modal's purpose
2. **Actionable Language**: Use specific, actionable language for buttons and calls-to-action
3. **Error Handling**: Provide clear error states and recovery options within modals
4. **Loading States**: Show appropriate loading indicators for async operations
5. **Mobile Optimization**: Design modal content that works well on touch devices
