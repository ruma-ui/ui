## Overview

The Popover component is a compound component system that provides flexible content display in overlay panels. Unlike dropdown menus, popovers can contain rich content including forms, images, and interactive elements. The component offers multiple trigger types with isolated event handling, comprehensive alignment options including perfect center positioning, smart positioning, and comprehensive accessibility features that align with the design system.

<Canvas of={PopoverStories.Primary} />

## Basic Usage

The Popover component uses a compound pattern with multiple sub-components. The `Popover` provides context and behavior, `PopoverTrigger` handles the trigger element, and `PopoverContent` contains the overlay content.

```tsx
<Popover>
    <PopoverTrigger asChild>
        <Button variant="outline" endIcon={<FaInfoCircle />}>
            Show Info
        </Button>
    </PopoverTrigger>
    <PopoverContent className="w-80">
        <div className="space-y-3">
            <h4 className="font-semibold text-gray-900">About this feature</h4>
            <p className="text-sm text-gray-600">
                This is a popover component that can contain rich content.
            </p>
        </div>
    </PopoverContent>
</Popover>
```

## Trigger Types

### Click Trigger

The default trigger type opens the popover on click and closes it when clicking outside or pressing Escape. Click triggers are isolated from focus events, ensuring predictable behavior.

<Canvas of={PopoverStories.Primary} />

### Hover Trigger

Hover triggers display the popover when hovering over the trigger element, useful for tooltips and quick previews. The popover appears on mouse enter and disappears on mouse leave.

<Canvas of={PopoverStories.HoverTrigger} />

### Focus Trigger

Focus triggers show the popover when the trigger element receives focus, ideal for form help text and accessibility. The popover remains open when focusing on the popover content and only closes when focus moves completely away from both the trigger and content.

## Alignments

The popover can be positioned relative to the trigger with comprehensive alignment options. Use the `align` prop on `PopoverContent` which defaults to "bottom-start". The component supports:

- **Bottom alignments**: `bottom-start`, `bottom-center`, `bottom-end`
- **Top alignments**: `top-start`, `top-center`, `top-end`
- **Side alignments**: `left`, `right`

The center alignments (`bottom-center`, `top-center`) perfectly center the popover relative to the trigger element, providing optimal visual balance.

## Component API

<ArgTypes of={PopoverStories} />

### Popover

The root component that provides context for the popover.

```tsx
<Popover open={open} onOpenChange={setOpen} trigger="click">
    {/* children */}
</Popover>
```

**Props:**

- `children`: ReactNode - The popover content
- `open?`: boolean - Controlled open state
- `defaultOpen?`: boolean - Default open state (default: false)
- `onOpenChange?`: (open: boolean) => void - Callback when open state changes
- `trigger?`: "click" | "hover" | "focus" - How the popover is triggered (default: "click")

### PopoverTrigger

The trigger element that opens/closes the popover.

```tsx
<PopoverTrigger asChild>
    <Button>Open Popover</Button>
</PopoverTrigger>
```

**Props:**

- `children`: ReactNode - The trigger element content
- `asChild?`: boolean - Whether to merge props onto the child element (default: false)

### PopoverContent

The content container for the popover overlay.

```tsx
<PopoverContent position="bottom" align="start" className="w-64" closeOnClick offset={8}>
    {/* popover content */}
</PopoverContent>
```

**Props:**

- `children`: ReactNode - The popover content
- `align?`: "bottom-start" | "bottom-center" | "bottom-end" | "top-start" | "top-center" | "top-end" | "left" | "right" - Alignment relative to trigger (default: "bottom-start")
- `className?`: string - Additional CSS classes
- `closeOnClick?`: boolean - Whether clicking inside closes the popover (default: false)
- `offset?`: number - Offset from trigger element in pixels (default: 8)
- `autoPosition?`: boolean - Whether to automatically adjust position based on available viewport space (default: true)

## Accessibility

The Popover component follows WAI-ARIA guidelines and includes comprehensive accessibility features:

- **Keyboard Navigation**: Full keyboard support with Escape key to close and proper focus management
- **Screen Reader Support**: Proper ARIA attributes including `aria-expanded` and `role="dialog"`
- **Focus Management**: Intelligent focus handling that preserves focus within popover content for focus triggers, while maintaining clear focus indicators and logical focus flow
- **Click Outside**: Automatically closes when clicking outside the popover (for click triggers)
- **Trigger Isolation**: Each trigger type has isolated event handling to prevent interference between click, hover, and focus behaviors
- **Multiple Triggers**: Support for click, hover, and focus triggers with appropriate and predictable behavior patterns

## Best Practices

### When to Use

- **Rich Content Display**: For showing detailed information, forms, or interactive content in an overlay
- **Contextual Help**: For providing help text, tooltips, or additional information
- **Quick Actions**: For displaying action panels or mini-forms without full page navigation
- **User Profiles**: For showing user information or quick profile actions
- **Settings Panels**: For inline settings or configuration options

### When Not to Use

- **Simple Tooltips**: Consider using native tooltips or simpler solutions for basic text-only hints
- **Navigation Menus**: Use the Dropdown component for menu-style navigation
- **Large Forms**: Consider modals or dedicated pages for complex forms
- **Critical Actions**: Use modals for actions that require explicit user confirmation

### Guidelines

1. **Appropriate Content**: Keep popover content focused and relevant to the trigger element
2. **Reasonable Size**: Don't make popovers too large - they should feel lightweight and contextual
3. **Clear Triggers**: Use descriptive trigger text or icons that clearly indicate what the popover contains
4. **Smart Positioning**: Choose alignment that prevents the popover from being cut off by viewport edges. Use center alignments for optimal visual balance when appropriate
5. **Trigger Selection**: Choose the right trigger type - click for interactive content, hover for quick previews, focus for form help
6. **Consistent Behavior**: Use consistent trigger types and behaviors throughout your application
7. **Mobile Considerations**: Ensure popovers work well on touch devices and small screens
