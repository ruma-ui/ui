## Accessibility

This component follows accessibility best practices:

- Uses semantic HTML with proper `input[type="checkbox"]` elements
- Supports keyboard navigation (Tab, Space, Enter)
- Provides proper ARIA attributes
- Includes focus management and visual focus indicators
- Supports screen readers with proper labeling
- Implements the indeterminate state correctly
- Provides error announcements for screen readers

## Best Practices

### Do's ✅

- Use clear, descriptive labels placed to the right by default
- Associate labels with inputs (wrap input with a `<label>` or use `htmlFor`)
- Use checkboxes for multi-select; use radios when only one option can be selected
- Group related options with a group label and optional description
- Use the indeterminate state to reflect partial selection in a parent “Select All”
- Keep touch targets large enough (at least 40–44px for comfortable tapping)
- Allow users to change their selection without surprises; persist state where appropriate

### Don'ts ❌

- Don’t use a checkbox when the user must pick exactly one option (use radios)
- Don’t pre-check options for marketing/consent; require explicit opt-in
- Don’t rely on color alone to convey state; keep the checkmark visible and provide focus outlines
- Don’t introduce layout shifts on check/uncheck; icon should animate without moving content
- Don’t cram many options without spacing; use vertical lists for long groups and wrap smartly horizontally
- Don’t mix checkboxes and radios in the same logical group

### Common Patterns

```jsx
// Parent with Select All and indeterminate state handled by CheckboxGroup
<CheckboxGroup
    label="Notifications"
    enableSelectAll
    selectAllLabel="Enable all"
    options={[
        { value: "email", label: "Email" },
        { value: "push", label: "Push" },
        { value: "sms", label: "SMS" },
    ]}
    checkboxProps={{ animation: true }}
/>
```
