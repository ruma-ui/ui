## Overview

The Pagination component provides navigation controls for paginated content. It displays page numbers with previous/next buttons and supports ellipsis for large page counts. Built with accessibility, keyboard navigation, and responsive design in mind.

## Component API

<ArgTypes of={Pagination} />

### Pagination `currentPage`

The current active page number (1-indexed). This determines which page button appears active and affects the visible page range.

```tsx
<Pagination currentPage={3} totalPages={10} onPageChange={setCurrentPage} />
```

### Pagination `totalPages`

The total number of pages available. If totalPages is 1 or less, the component renders nothing.

```tsx
<Pagination currentPage={1} totalPages={25} onPageChange={setCurrentPage} />
```

### Pagination `onPageChange`

Callback function called when the user clicks a page button or navigation control. Receives the new page number as an argument.

```tsx
const [currentPage, setCurrentPage] = useState(1);

<Pagination
  currentPage={currentPage}
  totalPages={10}
  onPageChange={page => {
    setCurrentPage(page);
    // Additional logic like API calls
  }}
/>;
```

### Pagination `maxVisiblePages`

Controls how many page number buttons are visible at once. When the total pages exceed this number, ellipsis (...) appears to indicate skipped pages.

```tsx
// Show maximum 7 page buttons
<Pagination maxVisiblePages={7} currentPage={5} totalPages={20} onPageChange={setCurrentPage} />
```

## Accessibility

The Pagination component follows WCAG guidelines and accessibility best practices:

- **Semantic HTML**: Uses `<nav>` element with proper `aria-label`
- **ARIA Labels**: All buttons have descriptive `aria-label` attributes
- **Current Page**: Active page button has `aria-current="page"`
- **Keyboard Navigation**: Full keyboard support with logical tab order
- **Screen Reader Support**: Clear announcements for page changes and navigation
- **Focus Management**: Visible focus indicators and proper focus behavior
- **Disabled States**: Properly communicated via `aria-disabled` and `disabled` attributes

## Best Practices

### Do's ✅

- Always provide a clear `onPageChange` handler
- Use appropriate `maxVisiblePages` for your use case (5-7 is usually ideal)
- Show first/last buttons for datasets with more than 20 pages
- Consider the total number of pages when choosing size
- Provide visual feedback for the current page
- Test with keyboard navigation
- Use consistent pagination across similar interfaces

### Don'ts ❌

- Don't hide pagination for small datasets (2-3 pages still benefit from it)
- Avoid very large `maxVisiblePages` values (>10) as it creates clutter
- Don't disable pagination without clear user feedback
- Avoid inconsistent page numbering (always start from 1)
- Don't use pagination for very small datasets (< 10 items total)

### Common Patterns

```tsx
// Basic pagination
const [currentPage, setCurrentPage] = useState(1);
const itemsPerPage = 20;
const totalItems = 247;
const totalPages = Math.ceil(totalItems / itemsPerPage);

<Pagination
  currentPage={currentPage}
  totalPages={totalPages}
  onPageChange={setCurrentPage}
/>

// With API integration
const handlePageChange = async (page: number) => {
  setCurrentPage(page);
  setLoading(true);
  try {
    const response = await fetch(`/api/items?page=${page}&limit=${itemsPerPage}`);
    const data = await response.json();
    setItems(data.items);
  } catch (error) {
    console.error('Failed to load page:', error);
  } finally {
    setLoading(false);
  }
};

<Pagination
  currentPage={currentPage}
  totalPages={totalPages}
  onPageChange={handlePageChange}
  disabled={loading}
/>

// Data table pagination
<div className="flex items-center justify-between">
  <div className="text-sm text-gray-700">
    Showing {startItem} to {endItem} of {totalItems} results
  </div>
  <Pagination
    currentPage={currentPage}
    totalPages={totalPages}
    onPageChange={setCurrentPage}
    size="sm"
  />
</div>
```
