## Overview

The Resizable component provides a flexible container that allows users to adjust the size of content by dragging resize handles. It's perfect for creating resizable panels, editors, viewers, and other interactive UI elements that need dynamic sizing capabilities.

<Canvas of={ResizableStories.Default} />

## Basic Usage

The most basic usage of the Resizable component wraps any content and makes it resizable in both directions.

```jsx
<Resizable>
  <div>Your content here</div>
</Resizable>
```

### Resizable `direction`

The `direction` prop controls which resize handles are displayed and which directions are allowed for resizing.

```jsx
{
  /* Horizontal resizing only */
}
<Resizable direction="horizontal">
  <div>Content</div>
</Resizable>;

{
  /* Vertical resizing only */
}
<Resizable direction="vertical">
  <div>Content</div>
</Resizable>;

{
  /* Both directions (default) */
}
<Resizable direction="both">
  <div>Content</div>
</Resizable>;
```

### Resizable `onResize`, `onResizeStart`, `onResizeEnd`

Handle resize events for custom logic and state management.

```jsx
function MyComponent() {
  const [size, setSize] = useState({ width: 300, height: 200 });

  return (
    <Resizable
      onResize={newSize => {
        console.log("Resizing:", newSize);
        setSize(newSize);
      }}
      onResizeStart={() => console.log("Resize started")}
      onResizeEnd={finalSize => console.log("Resize ended:", finalSize)}
    >
      <div>
        Current size: {size.width}x{size.height}
      </div>
    </Resizable>
  );
}
```

## Accessibility

The Resizable component follows accessibility best practices:

- **Keyboard Navigation**: Resize handles are focusable and support arrow key resizing
- **Screen Reader Support**: Proper ARIA labels and roles for assistive technologies
- **Focus Management**: Clear focus indicators and logical tab order
- **Semantic HTML**: Uses appropriate ARIA attributes for slider-like behavior
- **High Contrast**: Resize handles have sufficient contrast and hover states

### Keyboard Controls

- **Tab**: Move focus to resize handles
- **Arrow Keys**: Resize the container (10px increments)
- **Enter/Space**: Activate resize mode (if supported by implementation)

## Best Practices

### Do's ✅

- Set appropriate min/max constraints to prevent unusable sizes
- Provide clear visual feedback during resize operations
- Use consistent handle colors across your application
- Consider touch interfaces when setting handle sizes
- Test with keyboard-only navigation
- Provide alternative ways to achieve the same functionality

### Don'ts ❌

- Don't make handles too small for touch interaction (minimum 44px recommended)
- Avoid hiding handles completely unless there's a clear alternative
- Don't set min/max constraints that make the component unusable
- Avoid using resize for critical layout elements that shouldn't change
- Don't rely solely on color to indicate interactive elements

### Performance Considerations

- Resize events fire frequently during drag operations
- Debounce resize callbacks if performing expensive operations
- Consider using `requestAnimationFrame` for smooth animations
- Avoid heavy re-renders during resize by memoizing content

### Use Cases

**Good for:**

- Code editors and IDE panels
- Image viewers and media players
- Dashboard widgets and charts
- Form builders and layout tools
- Split-pane interfaces

**Not ideal for:**

- Fixed-layout content
- Mobile-first responsive designs
- Content that must maintain specific aspect ratios
- Critical UI elements that shouldn't be resized
