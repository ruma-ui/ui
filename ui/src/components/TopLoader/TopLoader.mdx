## Overview

The TopLoader component provides a sleek, animated progress bar that appears at the top of the viewport. It's perfect for indicating loading states during page transitions, API calls, file uploads, or any async operation that requires visual feedback. The component supports both determinate and indeterminate progress states with smooth animations.

## Component API

<ArgTypes of={TopLoaderStories} />

### TopLoader `progress`

The `progress` prop accepts a number between 0-100 for determinate progress, or `null` for indeterminate loading. Use `null` when you don't know the exact progress or duration.

### TopLoader `show`

Controls the visibility of the loader. Set to `false` to hide the loader completely. The component uses opacity transitions for smooth show/hide animations.

### TopLoader `size`

Choose from five predefined sizes (`xs`, `sm`, `md`, `lg`, `xl`) to control the height of the loader bar. The default `md` size works well for most applications.

### TopLoader `variant`

Select from semantic color variants (`primary`, `secondary`, `success`, `warning`, `error`) that align with your design system's color palette.

### TopLoader `color`

Override the variant colors with a custom hex color value. This gives you complete control over the loader's appearance while maintaining all other functionality.

### TopLoader `speed`

Control animation timing with three speed options:

- `slow`: 500ms transitions for deliberate, calming animations
- `normal`: 300ms transitions for balanced user experience
- `fast`: 200ms transitions for quick, responsive feel

### TopLoader `glow`

Add a subtle glow effect that creates a shadow based on the loader's color. This enhances visual prominence without being distracting.

### TopLoader `zIndex`

Control the stacking order of the loader. The default value of 50 ensures it appears above most content but can be adjusted for specific layout requirements.

## Accessibility

Our TopLoader component follows accessibility best practices:

- **Semantic HTML**: Uses proper ARIA attributes for screen reader support
- **Progress Indication**: Correctly communicates progress values to assistive technologies
- **State Communication**: Properly indicates loading states with `aria-valuenow`, `aria-valuemin`, and `aria-valuemax`
- **Screen Reader Friendly**: Includes descriptive `aria-label` for context
- **Keyboard Navigation**: Doesn't interfere with keyboard navigation as it's a passive indicator
- **Color Contrast**: All variants meet WCAG color contrast requirements
- **Motion Preferences**: Respects user's motion preferences through CSS transitions

## Best Practices

### Do's ✅

- Use indeterminate mode for operations of unknown duration
- Use determinate mode when you can provide accurate progress feedback
- Position the loader at the top of the viewport for maximum visibility
- Choose appropriate sizes based on your application's visual hierarchy
- Use semantic variants (success, warning, error) to provide contextual feedback
- Combine with other loading indicators for complex operations
- Test with real user scenarios to ensure appropriate timing

### Don'ts ❌

- Don't use the loader for operations that complete instantly
- Avoid blocking user interaction unless absolutely necessary
- Don't place multiple loaders on the same page simultaneously
- Avoid using the loader for background operations that don't affect the UI
- Don't rely solely on color to convey meaning (combine with text when possible)

### Usage Patterns

```jsx
// Basic indeterminate loading
<TopLoader progress={null} show={isLoading} />

// File upload with progress
<TopLoader
  progress={uploadProgress}
  show={isUploading}
  variant="primary"
  size="md"
/>

// Page transition
<TopLoader
  progress={null}
  show={isNavigating}
  variant="primary"
  speed="fast"
/>

// Form submission
<TopLoader
  progress={null}
  show={isSubmitting}
  variant="primary"
  glow
/>

// Custom branded loader
<TopLoader
  progress={loadingProgress}
  show={isLoading}
  color="#your-brand-color"
  size="lg"
  glow
/>
```

### Integration Examples

```jsx
// With React Router
import { useLocation } from "react-router-dom";

function App() {
  const location = useLocation();
  const [isLoading, setIsLoading] = useState(false);

  useEffect(() => {
    setIsLoading(true);
    // Simulate route loading
    const timer = setTimeout(() => setIsLoading(false), 1000);
    return () => clearTimeout(timer);
  }, [location]);

  return (
    <>
      <TopLoader progress={null} show={isLoading} />
      {/* Your app content */}
    </>
  );
}

// With API calls
function DataComponent() {
  const [loading, setLoading] = useState(false);
  const [progress, setProgress] = useState(0);

  const fetchData = async () => {
    setLoading(true);
    setProgress(0);

    try {
      // Simulate progress updates
      for (let i = 0; i <= 100; i += 20) {
        setProgress(i);
        await new Promise(resolve => setTimeout(resolve, 200));
      }

      await apiCall();
    } finally {
      setLoading(false);
    }
  };

  return (
    <>
      <TopLoader progress={progress} show={loading} />
      <button onClick={fetchData}>Load Data</button>
    </>
  );
}
```
