### Tooltip `position`

The `position` prop determines where the tooltip appears relative to the trigger element. The "auto" position automatically selects the best position based on available viewport space, following the priority order: top → left → right → bottom.

```jsx
<Tooltip content="Auto-positioned tooltip" position="auto">
  <Button>Auto</Button>
</Tooltip>
<Tooltip content="Top positioned tooltip" position="top">
  <Button>Top</Button>
</Tooltip>
<Tooltip content="Bottom positioned tooltip" position="bottom">
  <Button>Bottom</Button>
</Tooltip>
<Tooltip content="Left positioned tooltip" position="left">
  <Button>Left</Button>
</Tooltip>
<Tooltip content="Right positioned tooltip" position="right">
  <Button>Right</Button>
</Tooltip>
```

### Tooltip `maxWidth`

The `maxWidth` prop controls the maximum width of the tooltip. It accepts predefined size options (`xs`, `sm`, `md`, `lg`, `xl`) or `none` for no maximum width. By default, tooltips have no maximum width and will size naturally based on their content. When a maxWidth is set, content will automatically wrap to fit within the constraint.

```jsx
<Tooltip content="Tooltip with small max width" maxWidth="sm">
  <Button>Small</Button>
</Tooltip>
<Tooltip content="Tooltip with no max width" maxWidth="none">
  <Button>No Max</Button>
</Tooltip>
```

## Accessibility

The Tooltip component follows accessibility best practices and includes:

- **Keyboard Navigation**: Full keyboard support with focus management
- **Screen Reader Support**: Proper ARIA attributes and roles
- **Focus Management**: Clear focus indicators and proper focus handling
- **Semantic HTML**: Uses appropriate ARIA roles and properties
- **Color Contrast**: All variants meet WCAG color contrast requirements
- **Motion Preferences**: Respects user's motion preferences for animations

## Best Practices

### When to Use

- **Contextual Help**: For explaining interface elements and their functions
- **Status Information**: For providing details about system states and indicators
- **Form Guidance**: For helping users understand form field requirements
- **Feature Explanations**: For describing complex features or options
- **Error Details**: For providing additional context about errors or warnings

### When Not to Use

- **Essential Information**: Don't hide critical information in tooltips
- **Long Content**: Keep tooltip content concise; use modals for detailed information
- **Mobile Interfaces**: Consider touch interactions on mobile devices
- **Complex Interactions**: Avoid complex interactive elements within tooltips
- **Frequent Changes**: Don't use tooltips for rapidly changing information

### Guidelines

1. **Concise Content**: Keep tooltip text brief and actionable
2. **Clear Language**: Use specific, understandable language
3. **Consistent Positioning**: Use consistent positions for similar elements
4. **Appropriate Timing**: Choose delay times that match user expectations
5. **Visual Hierarchy**: Use variants to indicate importance and type of information
6. **Performance**: Avoid excessive tooltip animations or complex positioning logic

### Content Guidelines

1. **Action-Oriented**: Focus on what users can do or what information they're receiving
2. **Context-Aware**: Provide information relevant to the current context
3. **Non-Redundant**: Don't repeat information that's already clear from the interface
4. **Helpful**: Ensure tooltips add value and improve user understanding
5. **Up-to-Date**: Keep tooltip content accurate and current

### Implementation Guidelines

1. **Positioning Logic**: Implement smart positioning that adapts to viewport boundaries
2. **Touch Support**: Consider touch interactions for mobile and tablet users
3. **Animation Performance**: Use performant animations that don't impact user experience
4. **Memory Management**: Properly clean up event listeners and timers
5. **Testing**: Test tooltips across different browsers and devices
