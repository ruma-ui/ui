## Accessibility

This component follows accessibility best practices:

- Semantic input elements with proper labeling via `label` + `htmlFor`
- `aria-invalid` and `aria-describedby` for errors and helper text
- Individual `aria-label` for each input slot with position context
- Keyboard navigation support (Arrow keys, Home, End, Backspace, Delete)
- Clear focus outline and sufficient contrast
- Screen-reader compatible with proper role and grouping
- Input mode hints for mobile keyboards (`numeric` for numbers)

## Best Practices

### Do's ✅

- Use clear labels describing what code the user should enter
- Provide helper text explaining where the code was sent
- Auto-focus the first input for better UX
- Use appropriate `type` (number vs text) based on expected input
- Show completion feedback when the code is entered
- Use `mask` prop for sensitive data like PINs

### Don'ts ❌

- Don't use overly long OTP codes (keep it between 4-8 characters)
- Avoid disabling paste functionality unless absolutely necessary
- Don't show errors before the user has attempted to enter the code
- Don't use for non-sequential input (use regular text inputs instead)

### Common Patterns

```jsx
// Email verification
<InputOTP
    label="Email Verification"
    description="Enter the 6-digit code sent to your email"
    length={6}
    autoFocus
    onComplete={(code) => verifyEmail(code)}
/>

// SMS authentication
<InputOTP
    label="SMS Code"
    description="Enter the 4-digit code sent to +1 (555) 123-4567"
    length={4}
    type="number"
    onComplete={(code) => verifySMS(code)}
/>

// Security PIN
<InputOTP
    label="Security PIN"
    description="Enter your 6-digit security PIN"
    length={6}
    mask={true}
    type="number"
    onComplete={(pin) => verifyPIN(pin)}
/>

// Product key
<InputOTP
    label="Product Key"
    description="Enter the 8-character product key"
    length={8}
    type="text"
    onComplete={(key) => activateProduct(key)}
/>
```
