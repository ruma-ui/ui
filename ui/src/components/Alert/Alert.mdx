## Overview

Alerts are used to communicate important messages to users, providing feedback about actions, system status, or contextual information. They support multiple variants for different message types, can include icons and titles, and offer dismissible functionality for enhanced user control.

<Canvas of={AlertStories.Info} />

## Variants

### Info Variant

Use info alerts to provide helpful information, tips, or neutral notifications that enhance user understanding without indicating success or failure.

<Canvas of={AlertStories.Info} />

### Success Variant

Success alerts confirm that an action has completed successfully, providing positive feedback to users about completed operations.

<Canvas of={AlertStories.Success} />

### Warning Variant

Warning alerts draw attention to important information that users should be aware of, indicating caution or potential issues that may need attention.

<Canvas of={AlertStories.Warning} />

### Error Variant

Error alerts communicate problems, failures, or critical issues that require immediate user attention or corrective action.

<Canvas of={AlertStories.Error} />

## Styles

### Filled Style

The filled style provides maximum visual impact with colored backgrounds, ideal for critical information that needs immediate attention.

### Soft Style

The soft style uses light background colors with subtle borders, providing a gentle way to convey information without overwhelming the interface.

### Alert `dismissible` and `onDismiss`

Make alerts dismissible to give users control over their interface. The `onDismiss` callback is triggered when the dismiss button is clicked.

```jsx
const [show, setShow] = useState(true);

{
  show && (
    <Alert dismissible onDismiss={() => setShow(false)} variant='info'>
      This alert can be dismissed
    </Alert>
  );
}
```

## Accessibility

Our Alert component follows accessibility best practices:

- **Semantic HTML**: Uses proper ARIA roles (`alert`, `alertdialog`, `status`) for screen reader compatibility
- **Keyboard Navigation**: Dismissible alerts support keyboard interaction (Enter and Space)
- **Screen Reader Support**: Proper labeling and role attributes ensure alerts are announced correctly
- **Focus Management**: Dismiss buttons are properly focusable and labeled
- **Color Independence**: Information is conveyed through icons and text, not just color
- **High Contrast**: Text maintains sufficient contrast ratios across all variants

## Best Practices

### Do&apos;s ✅

- Use appropriate variants that match the message type (error for failures, success for completions)
- Keep alert messages concise and actionable
- Include clear next steps or actions when relevant
- Use dismissible alerts for non-critical information
- Provide icons that enhance understanding
- Place alerts contextually near related content

### Don&apos;ts ❌

- Don&apos;t overuse alerts - they should be reserved for important information
- Avoid generic messages like "Something went wrong" - be specific
- Don&apos;t make critical alerts dismissible without ensuring users have seen them
- Avoid using only color to convey meaning
- Don&apos;t stack too many alerts - consider grouping or prioritizing

### Alert Placement Patterns

```jsx
// Page-level alerts
<Alert variant="warning" title="Maintenance Notice">
  System maintenance is scheduled for tonight from 2-4 AM EST.
</Alert>

// Form validation alerts
<Alert variant="error" dismissible>
  Please correct the highlighted fields before submitting.
</Alert>

// Inline contextual alerts
<Alert variant="info" size="sm" style="soft">
  This feature is currently in beta.
</Alert>
```

### Message Writing Guidelines

- **Be specific**: "Your password has been updated" vs "Changes saved"
- **Be actionable**: Include what users should do next when relevant
- **Be timely**: Use present tense for current states, past tense for completed actions
- **Be helpful**: Provide links or buttons for immediate next actions
