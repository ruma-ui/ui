## Overview

The Stepper component provides a visual representation of a multi-step process, guiding users through a sequence of steps. It displays progress, indicates the current step, and can optionally allow navigation between steps. The component is fully accessible and follows our design system patterns.

<Canvas of={StepperStories.Default} />

## Variants

### Default Variant

The default variant shows steps with circular indicators that change color based on their state. Completed steps show a checkmark icon, active steps are highlighted, and inactive steps are muted.

<Canvas of={StepperStories.Default} />

### Numbered Variant

The numbered variant displays step numbers instead of icons, providing a clear sequential progression that's easy to follow.

<Canvas of={StepperStories.Numbered} />

### Minimal Variant

The minimal variant uses subtle styling with lighter colors and smaller visual emphasis, perfect for less prominent step indicators.

<Canvas of={StepperStories.Minimal} />

## Orientations

### Horizontal Orientation

Horizontal steppers are ideal for wide layouts and work well in forms, wizards, and checkout flows.

<Canvas of={StepperStories.HorizontalSmall} />

### Vertical Orientation

Vertical steppers are perfect for narrow layouts and provide more space for step descriptions and content.

<Canvas of={StepperStories.VerticalDefault} />

### Stepper `steps`

The `steps` prop accepts an array of step objects that define the stepper's content and behavior.

```tsx
const steps = [
  {
    id: "personal-info",
    title: "Personal Information",
    description: "Enter your personal details",
    icon: <UserIcon />,
    disabled: false,
  },
  {
    id: "payment",
    title: "Payment Details",
    description: "Provide payment information",
    icon: <CreditCardIcon />,
  },
  // ... more steps
];

<Stepper steps={steps} activeStep={0} />;
```

### Stepper `onStepClick` and `onChange`

These callback props allow you to handle step navigation and state changes.

```tsx
const [activeStep, setActiveStep] = useState(0);

const handleStepClick = (stepIndex, step) => {
  console.log("Step clicked:", stepIndex, step);
  setActiveStep(stepIndex);
};

const handleChange = stepIndex => {
  setActiveStep(stepIndex);
};

<Stepper
  steps={steps}
  activeStep={activeStep}
  clickable={true}
  onStepClick={handleStepClick}
  onChange={handleChange}
/>;
```

## Accessibility

Our Stepper component follows accessibility best practices:

- **Semantic HTML**: Uses proper ARIA attributes and roles (`tablist`, `tab`, `aria-selected`, `aria-disabled`)
- **Keyboard Navigation**: Full support for arrow key navigation when clickable
- **Screen Reader Support**: Proper labeling and state announcements
- **Focus Management**: Clear focus indicators and logical tab order
- **Orientation Support**: Proper `aria-orientation` attribute for screen readers
- **State Communication**: Active, completed, and disabled states are properly communicated

## Best Practices

### Do's ✅

- Use clear, descriptive step titles that indicate the purpose of each step
- Keep step descriptions concise and actionable
- Use icons that clearly represent the step's purpose
- Maintain consistent step progression (don't skip steps unless necessary)
- Provide visual feedback when steps are completed
- Use appropriate sizes based on your layout and content density
- Consider vertical orientation for mobile or narrow layouts

### Don'ts ❌

- Don't use vague step titles like "Step 1", "Step 2"
- Avoid overly long step descriptions that clutter the interface
- Don't make steps clickable if the workflow doesn't support backward navigation
- Avoid mixing different variants within the same stepper
- Don't hide important step information behind tooltips
- Avoid using stepper for single-step processes
