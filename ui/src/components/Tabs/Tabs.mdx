## Overview

Tabs organize content into multiple sections that users can navigate between. They help manage information hierarchy and provide a clean way to switch between different views or categories of content. Our Tabs component is designed to be flexible, accessible, and consistent with our design system.

## Controlled vs Uncontrolled

### Uncontrolled Tabs

Uncontrolled tabs manage their own internal state. Use the `defaultValue` prop to set the initial active tab.

```jsx
<Tabs defaultValue="tab1">
  <TabList>
    <Tab value="tab1">Tab 1</Tab>
    <Tab value="tab2">Tab 2</Tab>
  </TabList>
  <TabPanel value="tab1">Content 1</TabPanel>
  <TabPanel value="tab2">Content 2</TabPanel>
</Tabs>
```

<Unstyled>

    <TabList>

    </TabList>
    <TabPanel value="uncontrolled1">
      <div className="rounded bg-gray-50 p-4">Uncontrolled tab 1 content</div>

### Controlled Tabs

Controlled tabs give you full control over the active tab state. Use the `value` and `onValueChange` props.

```jsx
const [activeTab, setActiveTab] = useState("tab1");

<Tabs value={activeTab} onValueChange={setActiveTab}>
  <TabList>
    <Tab value="tab1">Tab 1</Tab>
    <Tab value="tab2">Tab 2</Tab>
  </TabList>
  <TabPanel value="tab1">Content 1</TabPanel>
  <TabPanel value="tab2">Content 2</TabPanel>
</Tabs>;
```

### Tabs `defaultValue` and `value`

Use `defaultValue` for uncontrolled tabs and `value` for controlled tabs to manage the active tab state.

```jsx
// Uncontrolled
<Tabs defaultValue="tab1">
  <TabList>
    <Tab value="tab1">Tab 1</Tab>
  </TabList>
</Tabs>;

// Controlled
const [activeTab, setActiveTab] = useState("tab1");
<Tabs value={activeTab} onValueChange={setActiveTab}>
  <TabList>
    <Tab value="tab1">Tab 1</Tab>
  </TabList>
</Tabs>;
```

### Tabs `onValueChange`

The `onValueChange` callback is called when the active tab changes, providing the new tab value.

```jsx
<Tabs onValueChange={value => console.log("Active tab:", value)}>
  <TabList>
    <Tab value="tab1">Tab 1</Tab>
    <Tab value="tab2">Tab 2</Tab>
  </TabList>
</Tabs>
```

### Tab `value`

Each tab must have a unique `value` that corresponds to its associated `TabPanel`.

```jsx
<Tabs>
  <TabList>
    <Tab value="unique-id-1">Tab 1</Tab>
    <Tab value="unique-id-2">Tab 2</Tab>
  </TabList>
  <TabPanel value="unique-id-1">Content 1</TabPanel>
  <TabPanel value="unique-id-2">Content 2</TabPanel>
</Tabs>
```

### Tab `disabled`

## Accessibility

Our Tabs component follows accessibility best practices:

- **Semantic HTML**: Uses proper `<button>` elements with ARIA attributes
- **Keyboard Navigation**: Full support for Tab, Enter, and Space key navigation
- **Screen Reader Support**: Proper `role="tablist"`, `role="tab"`, and `role="tabpanel"` attributes
- **ARIA Attributes**: Correct `aria-selected`, `aria-controls`, and `aria-labelledby` relationships
- **Focus Management**: Clear focus indicators and logical tab order
- **Disabled States**: Properly communicated via `aria-disabled` attribute

## Best Practices

### Do's ✅

- Use clear, descriptive tab labels that indicate content type
- Maintain consistent tab structure across similar interfaces
- Limit the number of tabs (ideally 3-7) to avoid overwhelming users
- Use icons sparingly and only when they add clarity
- Ensure tab content is clearly differentiated
- Provide adequate spacing between tab content and other elements
- Use controlled tabs when you need to react to tab changes
- Test keyboard navigation thoroughly

### Don'ts ❌

- Don't use tabs for sequential processes (use wizards instead)
- Avoid vague labels like "Tab 1", "Tab 2"
- Don't nest tabs within tabs
- Avoid using tabs when content can fit on a single page
- Don't disable tabs without clear indication of why
- Avoid mixing controlled and uncontrolled patterns in the same component

### Tab Combinations
