## Overview

The MultiSelect component is a fully custom, accessible multi-selection dropdown interface that provides complete control over styling and behavior. Built with keyboard navigation, proper ARIA attributes, and modern design patterns for production-ready applications. It supports both controlled and uncontrolled usage patterns.

### MultiSelect `showSelectedCount`

The `showSelectedCount` prop controls how selected options are displayed in the trigger. When `true` (default), it shows a count like "2 of 5 selected". When `false`, it displays selected options as individual tags.

```jsx
<MultiSelect showSelectedCount={true} options={options} placeholder="Show count" />
<MultiSelect showSelectedCount={false} options={options} placeholder="Show labels" />
```

## Accessibility

The MultiSelect component follows WAI-ARIA guidelines and includes comprehensive accessibility features:

- **Keyboard Navigation**: Full keyboard support with arrow keys, Enter, Space, and Escape
- **Screen Reader Support**: Proper ARIA attributes and role definitions including `aria-multiselectable`
- **Focus Management**: Clear focus indicators and logical focus flow
- **Error Handling**: Accessible error messages linked to the multi-select element
- **Hidden Search**: Type-to-select functionality for quick navigation

## Best Practices

### When to Use

- **Multiple Selection**: When users need to choose multiple options from a list
- **Custom Styling**: When you need full control over appearance and behavior
- **Accessibility**: When you need comprehensive keyboard and screen reader support
- **Form Integration**: For advanced form handling with libraries like React Hook Form
- **Limited Choices**: When you want to restrict the number of selections with `maxSelections`

### When Not to Use

- **Single Selection**: Consider a regular Select component for single choices
- **Few Options**: Consider checkbox groups for simple 2-4 options
- **Search Required**: Consider a combobox or autocomplete component
- **Complex Hierarchies**: For deeply nested or hierarchical selections

### Guidelines

1. **Clear Labels**: Always provide descriptive labels for form accessibility
2. **Logical Ordering**: Order options alphabetically, by importance, or by frequency of use
3. **Default Values**: Use meaningful defaults or pre-select reasonable options
4. **Error Handling**: Provide clear, actionable error messages
5. **Consistent Sizing**: Use consistent sizes throughout your application
6. **Performance**: For large option lists, consider virtualization or server-side filtering
7. **Max Selections**: Use `maxSelections` to prevent user overwhelm and enforce business rules
8. **Display Mode**: Choose between count and label display based on your use case
