## Accessibility

The Progress component follows accessibility best practices and includes:

- **Semantic Progress Role**: Proper ARIA progressbar role with value attributes
- **Screen Reader Support**: Appropriate ARIA labels and value announcements
- **Keyboard Navigation**: Full keyboard accessibility for interactive elements
- **Color Contrast**: All variants meet WCAG color contrast requirements
- **Motion Preferences**: Respects user's motion preferences for animations

## Best Practices

### When to Use

- **Task Progress**: For showing completion status of long-running tasks
- **File Operations**: For upload/download progress tracking
- **Loading States**: For indeterminate progress during data fetching
- **Status Indicators**: For system metrics, storage usage, battery levels
- **Multi-step Processes**: For wizard or form completion progress
- **Data Processing**: For batch operations, imports, or exports

### When Not to Use

- **Instant Actions**: Use loaders for immediate feedback instead
- **Binary States**: Use toggles or checkboxes for simple on/off states
- **Navigation**: Don't use progress bars as navigation elements
- **Exact Values**: Consider other components when precise numeric display is critical
- **Small Spaces**: Use alternative indicators in very constrained layouts

### Guidelines

1. **Clear Purpose**: Always provide context for what the progress represents
2. **Appropriate Animation**: Use animation sparingly and respect motion preferences
3. **Consistent Variants**: Use the same variants for similar types of progress
4. **Value Ranges**: Ensure progress values stay within 0-100 range
5. **Loading States**: Use indeterminate progress when exact progress is unknown
6. **Performance**: Avoid updating progress too frequently to prevent UI lag

### Content Guidelines

1. **Descriptive Labels**: Use clear, actionable labels that users understand
2. **Progress Units**: Specify units when percentages aren't meaningful (MB, items, etc.)
3. **Status Communication**: Use appropriate variants to communicate progress status
4. **Error Handling**: Show clear error states when progress fails
5. **Completion Feedback**: Provide clear completion feedback and next steps

### Animation Guidelines

1. **Smooth Transitions**: Use consistent animation timing for value changes
2. **Motion Preferences**: Respect user's reduced motion preferences
3. **Performance**: Avoid complex animations that could impact performance
4. **Purposeful Animation**: Only animate when it adds value to the user experience
5. **Consistent Timing**: Use consistent animation durations across the application
